首页联系作者区域已接入个人微信二维码和 `pickyan@163.com`，支持原图查看、保存和邮箱复制。移动端优化覆盖顶部导航、联系卡、触摸下拉选项与表单字体；`scripts/contact-mobile-qa.mjs` 验证原图一致性、弹窗、剪贴板及320–1440像素布局。

正式站现使用 Next.js 16 App Router + React 19 + Neon，GitHub Actions 每30分钟计划采集。开发：`npm ci`、`npm run dev`；生产：`npm run build`、`npm start`。页面地址支持 `/search`、`/compare`、`/lottery` 等，旧 hash 链接保留兼容。已有工具与动画继续复用，尚未逐项重写为 React 状态组件。架构、部署与检查见 [Next.js 迁移说明](docs/next-migration.md)。

以下包含此前版本及本地 SQLite 工具的说明；原本机服务改用 `npm run start:local`，正式站以 Next.js 迁移说明为准。

首屏先读取最新有效采样；历史行情在进入趋势或行情时加载。图鉴按页面与悬停意图预加载，节省流量模式减少图片预取。预览保留官方原图，新增实际分辨率、原图比例与展开检视；切帧先解码再显示，保留当前画面并支持失败重试。鼠标指针中心缩放、双击缩放、双指缩放和缩放后单指平移使用逐帧调度。比较图片也采用解码缓存和逐帧绘制。

新增卡片入场、悬停和按压反馈，并遵循减少动态效果设置；搜索取消过时请求，保留当前结果直到新结果返回。测试包括真实 Neon 数据、延迟/失败原图、真实触摸事件及手机边界，未使用模拟行情。详见 `scripts/experience-qa.mjs`。

新增 Vercel + Neon + GitHub Actions 适配：云端 PostgreSQL、库存 SQL 分页、历史游标读取、独立抽签史低基线和30分钟定时采集。配置步骤见 [VERCEL_SETUP.md](VERCEL_SETUP.md)。部署需要设置 `DATABASE_URL`；账号未配置前不表示远程服务已上线。云端版本暂未开放微信登录与公众号发送。

搜索默认覆盖全部已收录库存，支持切换本轮样本、近65分钟观察过滤、最近观察排序。记录展示观察时间，支持详情核验和价格变动提示；无法确认的商品标记不可见，不冒充已成交。静态版本使用精简库存索引，预览与比较按品类延迟读取完整多角度原图，保存条件与导出继续可用。

## V2.1 · 抽签提醒与全部公开分页收集

抽签提醒页面已接通无需登录的本机订阅：同款＋已解锁孔数分组，允许在首次出现抽签前订阅。网页打开时自动检查新采样，只对订阅之后且仍有效、最近40分钟的严格新低写入本机收件箱；不重放首次基线、已读、过期或已变化的商品。浏览器系统通知需用户点击按钮授权，不支持/拒绝时站内收件箱仍可用。关闭网页后浏览器提醒不会运行。本机设置只在当前浏览器保存，微信服务端订阅独立存在；公众号/模板/发送凭证当前未配置，不会发送微信提醒。

新增即时核验 `GET /api/lottery/verify?id=...`：仅查询已收集/已采样的真实商品，使用固定官方详情接口，不接受任意上游地址；核验后只为仍有效的抽签提供官方入口。采样超过65分钟时不显示直接购买链接。静态站点没有该API，页面明确提示到藏宝阁核实或使用完整本机服务。

采集器每30分钟先读官方全部29种类型的低价首页，`pass_fair_show=''` 经实测包含公示及非公示（服务端每页实际返回15件，不能通过count=100扩大）。随后轮流深入每款未读分页，校验实际页码与总页数，保存断点；每轮请求间隔至少1.6秒、预算6分钟/220请求、最多100次详情核验，到预算即保存并交给下一轮继续。全部类型遍历后开始下一轮滚动扫描；分页变化及移动排序可能造成遗漏，所以不宣称同时点全市场完整快照。遇验证/限流/结构异常停止，不绕过。

商品档案与每次价格/收藏观察保存在 `data/inventory.sqlite`，与现有行情历史分开；已读/总页数、不同商品数、每款状态显示在抽签提醒页面。历史档案不推断当前库存或成交，保留第一次/最后一次观察时间、孔数、锁孔、价格、收藏和官方预览URL。抽签详情候选持久化，后续轮次继续核验。详情观察时间会随批次保存，避免长轮次结束前已截止的短窗口被错误丢弃为历史缺失。

`GET /api/collection` 返回实际进度，`GET /api/inventory?type=...&page=...` 分页读取商品档案。每轮将进度与分类型商品导出到 `dist/collection.json`、`dist/inventory/` 供静态发布读取；可手动 `node scripts/export-inventory.mjs` 导出。首页价格趋势仍使用明确标注的低价首页/已确认抽签样本，不将跨时段档案拼成“当前全部在售”。

2026-10-21首轮扩展采集成功：29种类型均开始读取，154/852页、2,174件不同商品、17次抽签详情核验；无采集错误，尚未遍历全部页。后续Windows任务自动使用新采集器断点续采（电脑需开机、联网且用户已登录）。本机服务支持持续更新和即时核验；线上Sites版本仍为发布时快照，不会自动同步本机任务。

验证：`npm test`（30项）、`node scripts/lottery-qa.mjs`（真实数据、本机订阅、核验、档案分页/预览及手机）、门户和静态快照回退检查。

## V0.8：单孔外观图鉴导入

图鉴主区域新增公开图鉴导入：`node scripts/import-atlas.mjs` 通过参考站公开 `/gallery/items?equip_type=` 接口逐类型读取（接口文档声明自动分页取全），请求间隔1.6秒，无并发、无绕过。2026-10-20首次成功读取29/29种类型，114,537条变体来源记录，78,122个“类型＋孔位＋数值”索引。2P接口返回空数组，明确显示无星格/无记录，不补数据。`dist/atlas/index.json` 记录来源、时间、每种数量和请求状态，分类型JSON按需加载；保存的是数值及官方截图地址，不下载参考站自制缩略图，不复制其专有洗练算法。

单孔图鉴可筛选类型、孔位和数值范围，分页查看每值代表图、32帧旋转预览、加入比较。代表图仍为整件来源商品，完整数值同时展示以供核对；不推断组合渲染，不承诺全部合法数值均被收录。图鉴记录售价/收藏为空，状态为archive，不进入市场数据库或价格趋势；比较时隐藏还价入口。官方原图可能过期，页面提供明确失败提示。

洗练样本演练纳入当前类型导入的真实组合，起始下拉最多列300组，候选池仍使用全部同条件去重样本；新增独立单孔外观选择器，选择某数值会填入精确目标。各孔图片来自各自代表商品，不能合并理解为同一件商品外观。仍不把市场样本比例当作官方洗练概率。检查：`node scripts/atlas-qa.mjs`。

本轮暂停扩展登录功能，完善比较工作台：

- `#search` 自定搜索：名称/编号、角色/武器、同款、已解锁孔数、四格数值范围、指定格已解锁、预算、收藏、公示/抽签状态；条件可命名保存在本浏览器，可导出结果或转入趋势。
- `#gallery` 图鉴：从藏宝阁公开游戏配置读取29种谪星定义、所属英雄/武器、品质和星格名称；按真实观察样本筛选星格数值，查看整件原图并加入比较。未收录外观不生成占位商品，样本范围不冒充全部合法范围。
- `#simulator` 洗练样本演练：以真实完整组合为起点，按相同孔数和解锁形态筛选，固定指定星格，设置目标范围，单次或100次抽取，记录最近20次和自填消耗。**未取得官方洗练概率/消耗规则；等权抽样只演练已观察组合，样本占比不等于游戏成功率，也不提供官方期望成本。** 每次选择完整真实元组，不拼接不存在的数值。
- `#trends` 条件趋势：24小时/7天/30天实际观察时间轴，最低挂牌价、最低三件中位数、同条件另一谪星对照、区间首末变化与CSV。失败、无匹配和超过54分钟间隔断线；采样范围变化也可能改变底价，非成交价格与全市场史低。
- 比较增强：搜索/图鉴直接加入、跨页面比较浮动入口、前两件透明叠加检视，与原比较角度/缩放同步。

官方定义缓存 `dist/catalog.json` 随每轮采集更新，也可单独执行 `node scripts/update-catalog.mjs`。新功能测试：`npm test`、`node scripts/tools-qa.mjs`、`node scripts/compare-fee-qa.mjs`；浏览器检查使用真实本机数据库，不注入模拟行情。线上静态发布仍是发布时行情快照，持续30分钟更新需打开本机完整服务。

新增“外观预览”：在市场列表点击“预览”或商品行，打开与藏宝阁同源的多角度原图序列。支持左右拖动切换角度、方向键/滑块选角度、1—6倍放大、滚轮/双指缩放、拖动平移、明暗背景、复位及原图链接。抽签列表中仍在抽签的商品也提供预览入口。切换“观察记录”可查看该件商品历史。

右上角新增“登录 / 注册”入口：接入官方内嵌微信登录组件，启用本机微信快捷授权和扫码回退；首次授权自动注册，后续复用账号。登录后显示微信允许返回的昵称/头像，支持退出。网站应用登录独立于公众号，可先配置 `WECHAT_WEB_APP_ID`、`WECHAT_WEB_APP_SECRET` 和 `SITE_ORIGIN`。当前凭证待管理员在HTTPS后端配置，未配置时不会生成无效二维码或假登录态。详细要求及真实账号联调步骤见 [微信接入说明](docs/wechat-setup.md)。浏览器适配检查：`node scripts/auth-qa.mjs`；测试中的组件与身份桩仅用于隔离检查，不会部署为用户登录方式。

新增“谪星比较”（`#compare`）：在商品行点击“比较”，或粘贴永劫无间藏宝阁商品链接，每行一个。最多8件并排，支持同步角度、同步放大/平移、水平辅助线、明暗背景、亮度/对比度/饱和度、比较基准和数值差异提示。比较列表保存在浏览器，可移除、清空；价格、收藏、孔数、锁孔与观察时间同时展示。显示调整只作用于浏览器图像，不修改来源图片，数值高低不等于外观优劣。

链接导入优先匹配本次采集商品；未收录商品由完整Node服务 `/api/compare/item` 查询官方详情，缓存5分钟，请求至少间隔1.5秒。端点仅接受官方商品链接并使用固定官方上游，禁止任意地址代理。线上静态快照只能比较已收录商品；完整服务支持加载其他有效商品链接。比较卡片可将挂牌价带入还价试算。

费用计算器（`#calculator`）保留挂价算到手、目标到手反推挂价和盈亏，新增“还价＋补差额”模式、8折/9折快捷按钮、双方分摊和结果复制。可按原挂价或卖家目标到手输入。参考 [谪星比比比较页](https://zhexing.emoyilab.com/compare) 与 [费用试算页](https://zhexing.emoyilab.com/fee-calc) 的交互思路独立实现；8%费率、80%最低还价比例是参考工具预设，均可修改，并非已核实的平台固定规则。额外补差仅作数学试算，不执行交易；平台外付款不在平台交易保障范围内。

资源来自公开商品数据中的 `capture_url` 和 `other_info.capture_url`，常见为32帧；此次实测角色截图1884×900，不承诺所有商品同样分辨率或帧数。实现是官方截图序列检视，不是WebGL模型渲染；尚未取得或实现自由姿态、光照与模型文件。仅保存官方HTTPS图片URL，图片由浏览器按需加载，并预取相邻帧。失效时提供重试和藏宝阁原站入口，不生成替代图。媒体URL独立存储在SQLite media表，只在最新有效批次附带，避免每轮历史反复存储32帧链接。


## 导入数据

`priceCents` 使用整数分，`at` 必须带时区；`coverage` 为 complete（来源声称完整）、partial（部分覆盖）、failed（采集失败且items为空）。每个批次保存当轮已观察商品，不将商品缺失视为售出。

```powershell
npm run import -- 你的真实观察记录.json
```

数据库保存在 `data/market.sqlite`，不提交Git。同一批次时间再次导入会替换原批次。本机页面每分钟读取最新数据库；点击“刷新行情”可立即读取。采集失败留空，未出现的商品不被推断为售出。收藏变化取至少24小时前最近一条有效批次中的同ID记录；没有可比记录则留空。

可通过 `POST /api/import` 导入同格式数据。此端点默认禁用，需在服务端设置 `IMPORT_TOKEN` 并提交 `Authorization: Bearer ...`。`GET /api/data` 提供导入的历史记录。部署到公网前应增加访问控制；当前本地服务设计用于个人本机使用。

手动采集：`node scripts/collect.mjs`。安装Windows任务：在PowerShell运行 `./scripts/install-tasks.ps1`。`ZhexingCollector30m` 每30分钟执行，`ZhexingMarketServer` 登录后启动本机网页服务。任务仅在当前用户已登录、电脑开机且有网络时运行，不会唤醒电脑。采集日志为 `data/collector.log`，服务日志为 `data/server.log`。任务禁止并发，10分钟后自动清理上轮中断留下的锁；单轮最多运行8分钟。

停用：`Disable-ScheduledTask -TaskName ZhexingCollector30m`。恢复：`Enable-ScheduledTask -TaskName ZhexingCollector30m`。手动触发：`Start-ScheduledTask -TaskName ZhexingCollector30m`。

## 计算规则

平台费用 = min(封顶, max(最低手续费, 挂价×费率四舍五入至分))。
净到手 = 挂价 − 平台费用 − 其他卖家费用。反推用整数分二分搜索并正算校验。净收益 = 净到手 − 买入总成本。费率需满足0≤费率<100%。法定税款、优惠与未输入费用不自动纳入。

还价试算：Q为原挂价，B为平台还价，F为当前手续费规则，C为固定其他卖家费用。手续费差额 S=F(Q)−F(B)，买家分得金额 X=round(S×买家份额)，额外补差=Q−B−X，买家总支出=B+补差，卖家到手=B−F(B)−C+补差。买卖双方所得差额合计严格等于S，分取整的剩余部分归卖家。

例如Q=3000元、B=2400元、费率8%、无其他费用时，差额48元；归买家/各半/归卖家对应补差552/576/600元。若两种价格都触及同一最低费或封顶而手续费不变，则差额为0。比较报价前请确认实际平台规则和费用。

## 发布说明

`dist/market.json` 为采集后生成的真实快照。线上静态发布版可读取发布时快照，并明确提示不会随本机任务自动更新。本机30分钟采集会更新SQLite和该文件，但不会自动重新发布Sites。需要在线持续更新时，应将Node服务与数据库部署到持久化服务器，并在那里安装定时任务。
