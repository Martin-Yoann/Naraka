# 限量抽签候选与好价判断

定时采集仍由 GitHub Actions 每30分钟执行，默认不再按每个谪星类型遍历全部分页。

- 每轮读取最新上架最多4页、低价最多2页。只提取谪星，普通商品仅用于列表发现，不写入候选库存。
- 补充数据库里已知的当前抽签、近期将开签候选，优先核验当前抽签、接近开签及有价格依据的商品。
- 每轮最多核验32件详情、最多96件候选入队、总时限120秒；请求间隔1.6秒，与网页详情核验共享频率锁。页面手动刷新维持2页、12件、全站60秒冷却。
- 上游错误、验证或限流会停止本轮，部分成功照实保留，不尝试绕过验证。

`LOTTERY_UPCOMING_HOURS` 支持1–24小时，默认6小时。GitHub 仓库变量可配置该值；每轮采集完成后，实时刷新读取同一窗口配置。

## 时间判定

详情中的 `fair_show_end_time` 是预计开签依据，`random_draw_finish_time` 是抽签截止依据。列表时间只能发现候选，必须读取真实详情并确认截止晚于开始才可展示为即将开签。预计开始时间到达后，旧的公示状态不能自动转换成可参与状态，必须再次向藏宝阁核验 `is_random_draw_period`。超过65分钟未核验、已截止或状态不明的商品不进入好价列表。

## 价格依据

按同款谪星＋已解锁孔数分别比较。保留已确认抽签史低及其上一个低价，每组最多64件不同商品的最新已确认抽签价格样本；重复抓取同一商品不增加样本数量。

1. 低于此前已确认史低，或另一件商品达到此前史低：标为好价。
2. 近期比较只用30天内、有观察时间的不同商品样本，排除商品自身；相同解锁位置样本足够时优先比较同解锁位置，否则明确按同孔数比较。
3. 至少3件可比样本，5件以上按1.5倍四分位距剔除异常值；当前价低于样本中位价至少10%，且不高于较低四分位，标为近期好价。接近近期低价5%以内时标为接近近期低价，其他情况标为近期可比样本低价。
4. 首次收录没有历史依据时只建基线，不判好价。商品卡片提供样本数、参考范围和判断理由，未注明时间的旧样本不用于近期中位价。

预计开签商品的价格不会写入已确认抽签史低，也不会触发当前抽签购买提醒。原有账号提醒仍只针对已确认且未截止的抽签商品。好价标签不替代星格条件、外观比较或官方交易确认；有限采样中的低价不等于全市场最低或成交价格。

为建立后续判断依据，符合时间窗口但尚不够便宜的少量核验候选也会保存，页面默认展示全部已核验候选，可按好价、当前开抽、未来1/3/6小时、孔数和谪星筛选；可按时间、价格依据或价格排序。旧的全量记录按原有每72小时清理规则淘汰，史低汇总保留，不主动清空现有数据库。

## 单件商品收藏与开抽提醒

微信登录后每个账号最多收藏100件商品，独立于原有同款新低订阅。收藏、移除、开启或关闭开抽提醒均只对本账号生效。收藏接口只接受商品ID，商品资料由服务器从真实库存读取。

- 开抽提醒默认生成站内消息；微信模板配置就绪且用户明确勾选后，才开启微信渠道。仍沿用原有每账号每日3条微信额度。
- 已经开抽且近期核验有效的商品可以立即生成站内消息；未来商品只在真实详情确认开抽后生成，不按时钟猜测状态。
- 每次开启订阅只生成一次开抽消息，不因重复采样、价格变化或重复保存再次提醒。关闭后停止；移除收藏取消尚未发送的微信任务。
- 专项工作流约每5分钟仅核验临近开抽的收藏商品，单轮最多12件、使用共享详情限流；不进行全市场列表扫描。GitHub定时任务可能延迟，不能承诺准点提醒。常规候选采集继续每30分钟运行。
- 账号的全局提醒开关对收藏提醒和原有偏好提醒共同生效。微信发送前再次核验详情、权限和订阅状态，测试通知只发送到替身，不向真实用户发送开发测试消息。
